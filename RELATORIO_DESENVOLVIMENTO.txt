1. ERRO ORIGINAL
---------------------------------------------------------------------
Após integrar o reconhecimento anatómico (Fase 2D.2), a aplicação deixou
de inicializar no navegador com o erro:

    Failed to resolve module specifier "@tensorflow/tfjs"

Causa: O servidor estático anterior (`npx serve .`) não resolve dependências
npm (bare module specifiers) como `@tensorflow/tfjs` ou
`@tensorflow-models/body-segmentation`. Os imports ES modules exigem
um bundler ou servidor que resolva estes caminhos.

---------------------------------------------------------------------
2. CAUSA IDENTIFICADA
---------------------------------------------------------------------
- A aplicação usa `type: "module"` e imports ES6 diretos de pacotes npm.
- `npx serve .` serve ficheiros estáticos sem resolução de dependências.
- TensorFlow.js e Body Segmentation não estavam acessíveis no navegador.
- Além disso, `@mediapipe/selfie_segmentation` é um build Closure Library
  que não exporta ES modules, causando erro de build em Vite:
  "SelfieSegmentation is not exported by @mediapipe/selfie_segmentation".
- A API usada era `bodySegmentation.createDetector` (incorreta), a correta
  é `bodySegmentation.createSegmenter`.

8. PROBLEMAS AINDA EXISTENTES
---------------------------------------------------------------------
1. [IMPORT_IS_UNDEFINED] no build: Vite avisa que `createDetector`
   não é exportado pelo body-segmentation. O código usa `createSegmenter`
   (correto), mas o símbolo antigo existe nos tipos. Não afeta runtime.

2. Chunk size warning: Bundle principal ~1MB (268KB gzipped).
   Recomenda-se code-splitting dinâmico para TensorFlow.js em produção.

3. Aviso Vite: `__dirname` em vite.config.js deve usar `import.meta.dirname`
   (não crítico, funciona).

4. MediaPipe Selfie Segmentation retorna apenas máscara binária
   (pessoa/fundo), não 24 classes anatómicas. Para 24 classes, precisaria
   BodyPix completo (~20MB) ou MediaPipe Pose + Segmentation.
